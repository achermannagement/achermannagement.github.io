How to save website form data

Posted by Joshua Achermann in automation   

I want it to be simple

Continuing in my pattern of attempting things that seem simple at first, but turn into a rabbit hole. I was filling out a (single page) web form that was quite long and I needed to pause my progress, I wanted to capture my responses so that if accidently closed the page, I didn't lose my responses. Also I thought it would be good forward planning to keep a copy of my responses myself.

Of course, it is possible to copy and paste each response individually, but this is exactly the sort of repetitive toil I try to excise from my life.

The Initial Attempt

Sometimes the simplest solution works so we will try it. To select all page elements, the shortcut Ctrl+A works in many circumstances. Using the shortcut on our completed form, we want to see whether the input is also selected.

Unfortunately, this approach doesn't work as it only selects elements of the form itself and doesn't include my responses.

Autofilled forms?

Firefox and Chrome support autofill of forms for certain fields of the form which is great for repeated entry of your address etc. This usage is slightly different than what I wanted because I want to save all fields in a given form I am currently filling out, including fields that have never been seen before.

Extensions?

There are extensions which improve the experience of filling in longer forms, the main one I am aware of is Form History Control.

Copying the HTML

Let us look at the options for us built-in to the browser. These options both use the Developer Tools.

After I thought about why this happening, it made sense to me pretty quickly that copying the HTML markup was not going to return my responses. HTML is a markup language which defines the structure of webpages, it really doesn't concern itself with the interactivity of the webpage when it is being displayed by the web browser. We need to find a way to access the document as it is being presented by the browser.

Accessing the DOM

We can also access the DOM (Document Object Model) using the Developer Tools. It is an interface that lends itself to accessing the data of the objects that are present in the webpage as it being displayed. I created a small Javascript snippet that returns the contents of all input fields of selected element kinds.

  • <input> elements need to be selected as most user input occurs in them
  • <textarea> elements can be writable so we should grab their contents
  • <select> elements need to be included as dropdown selections use them
const formFields = document.querySelectorAll('input, textarea, select');
const fieldData = [];
formFields.forEach(field => {
  fieldData.push({
    name: field.name,
    value: field.value,
    autoname: field.attributes['autocomplete']
    });
});
var newWindow = window.open();
const formatted = fieldData.map(obj => JSON.stringify(obj)).join('\n');
newWindow.document.write('<pre>' + formatted + '</pre>'); })();

I have tested this code snippets with standard HTML forms as , then I tested it with some forms created in Google Forms as that is very popular. The form that trigger this inquiry was actually created by Cognito, I hadn't heard about this company before. It presented some problems with my first attempt at this code; the name attribute of the final output objects were not defined. I eventually found that there is an autocomplete attribute that contained the name of the given field so I simply included that in the dump as well.

Now we have Javascript code that accesses the DOM to get the content of input fields in a good variety of cases, how do we package it for easy usage?

Bookmarklets

A bookmarklet is a Javascript script that can run on click, similar to how a normal bookmark will trigger the browser to load the linked website.

Overall, it is a great idea. Once I have my code snippet inside the URI for the bookmarklet, it will open a new window with the list of objects (map containing the name, value and autocomplete) of the selected fields printed. The only thing I can complain about is that the entry for the bookmark URI is not designed to handle multiline input (because most bookmarket targets are usually a single line URL of course) so the developer UX leaves a lot to be desired.

Conclusion

Although, I could definitely improve the accessibility of using my bookmarklet (the output format of the form response dump is a bit ugly), I decided I was happy enough with the outcome of this exercise. I now get a simple dump of the name of the input elements along with their contents.

Some improvements I could envision myself making:

  • Iterating over the document top to bottom, dumping all HTML content alongside the field contents
  • Pretty printing the field data objects
  • Adding more metadata in the field data objects .eg types
